# 详细实施方案（PLAN）

> 项目：角斗士棋 Blokus 四人复刻版 ｜ 版本：v1.0 ｜ 日期：2026-10-06 ｜ 状态：M0–M7 已完成，M8（GitHub 远程仓库）等待用户一次性授权
> 机器可读进度见 `docs/plan/PLAN.json`，操作流水见 `docs/LOG.md`。

## 1. 目标与范围

### 1.1 目标

交付一个零依赖、零构建、无需部署的 4 人 Blokus 复刻版：浏览器直接运行，含启动器（单机 / 局域网）、
多人对局、进度保存、历史回放、棋谱导出、中英文界面、默认音效；为 AI 对手预留可二次开发的顶层设计与接口文档。

### 1.2 范围内

- R1–R12（见 AGENTS.md 第 2 节）全部实现。
- 单机热座 2–4 人；局域网联机 2–4 人。
- 标准规则与计分、pass 与终局判定。
- 存档、继续对局、历史列表、回放播放器、文本/JSON 棋谱导入导出。
- 文档：实施方案、设计文档、实施文档、AI 扩展接口、日志、协作规范。

### 1.3 范围外（本次不做，接口已预留）

- AI 对手实现（仅预留 PlayerController 接口与配置协议）。
- 公网对战、账号体系、排行榜、观战、聊天等。
- 移动端特殊适配（桌面优先，响应式布局做到可用级别）。
- 官方 Blokus 商标/图片素材。

## 2. 技术方案摘要

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 界面 | 原生 HTML + CSS，传统 script 标签 | 双击 index.html 即玩，不受 file:// 模块限制 |
| 渲染 | Canvas 2D | 20×20 棋盘与回放高亮性能好，逻辑简单 |
| 规则引擎 | js/pieces.js + js/rules.js + js/game.js（双端复用） | 浏览器与 Node 服务端共用同一份规则，避免双实现 |
| 存储 | localStorage（设置 / 历史索引 / 对局存档） | 零依赖、离线可用；导出 JSON 做备份与迁移 |
| 局域网 | Node 内置 http + REST + SSE | 零依赖，回合制棋类对延迟不敏感 |
| 音效 | WebAudio 合成 | 不引入二进制音频资源，默认开启、可关闭 |
| 国际化 | js/i18n.js 词条表 + data-i18n 扫描 | 无依赖，中/英切换即时生效并持久化 |
| 测试 | Node 直跑断言脚本 | 无需测试框架与安装 |

## 4. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| file:// 与 http:// 双环境差异 | 单机可用但联机异常 | 启动器检测 location.protocol，file:// 下禁用联机入口并给出指引 |
| 局域网无令牌导致他人占位 | 房间被冒用 | 加入时返回 playerToken，重连/提交均校验；房主可踢出 |
| 双端规则不一致 | 联机判罚争议 | 规则代码双端复用；服务端为最终裁判；测试同时覆盖 Node 与浏览器加载路径 |
| localStorage 上限（约 5 MB） | 历史对局过多 | 单局约几十 KB；超过阈值自动提示导出并清理最旧对局 |
| 回放数据与状态不一致 | 回放错位 | 回放只依赖 moves[] 顺序重放；每步可校验，发现不一致以 moves[] 为准 |
| GitHub 授权缺失 | 无法建远端仓库 | 先完成本地仓库与提交，最后请求用户一次性授权 |
